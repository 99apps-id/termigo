## A. Temuan Baru (belum ada di laporan sebelumnya)

### SEC-1 (HIGH) Hooks = persistence silent-exec lewat `.termigo/hooks.json`
- File: `src/modules/ai/lib/hooksRunner.ts` (fireHook), `src/modules/ai/lib/hooksIo.ts`, `src/modules/ai/lib/hooks.ts:9`
- Alur bug:
  1. `checkWritable(".termigo/hooks.json")` LOLOS - tidak ada guard khusus untuk file yang dieksekusi otomatis ini.
  2. Agent (termasuk lewat prompt injection dari web/file/orang Telegram) menulis satu baris hook `RunStop`/`PreToolUse`.
  3. `fireHook` menjalankan `rule.command` di SETIAP event tanpa approval UI; satu-satunya rem adalah `checkShellCommand` + sandbox Rust.
  4. Sandbox menolak nama program non-allowlist, TAPI `allows_program` selalu lolos untuk path absolut (BUG-6 lama, status DEFERRED). Payload tinggal ditaruh di workspace lalu dipanggil via path absolut: `<workspace>\.termigo\beacon.exe -f payload`.
- Impact: escalation persisten tanpa satu klik approval pun. Satu-satunya kontrol (allowlist) punya bypass yang sudah diketahui dan didefer.
- Rekomendasi:
  - Treating hooks as approval surface: snapshot hash `hooks.json` saat run mulai; kalau file berubah di tengah run, hook baru TIDAK fire sampai user approve (dialog "hooks changed, trust?").
  - Tambah `.termigo/` ke WRITE_DENY_PREFIXES di `security.ts` + mirror Rust, atau minimal khususkan `hooks.json`.
  - Kalau BUG-6 ditutup (mis. wajib exists + bukan di dalam workspace), sebagian vektor ini ikut mati.

### SEC-2 (MEDIUM) Mermaid render Telegram tanpa `securityLevel: "strict"`
- File: `src/modules/telegram/mermaidImage.ts:41` vs pembanding `src/components/ai-elements/mermaid-diagram.tsx:83` (sudah strict).
- `mermaid.initialize({ startOnLoad: false, theme: "base", ... })` tidak menyemat `securityLevel: "strict"`. Label non-strict pada mermaid mengizinkan htmlLabels/click handler; SVG sisipan bisa mengeksekusi JS di dalam webview aplikasi saat render.
- Trigger: kode mermaid dari balasan model / pesan Telegram yang diteruskan ke render.
- Fix: satu baris, samakan dengan `mermaid-diagram.tsx`.

### SEC-3 (MEDIUM, by-design tapi perlu disadari) `repl_send` = arbitrary code exec post-approval
- File: `src/modules/ai/tools/repl.ts` (repl_send, needsApproval: true), `src-tauri/src/modules/shell/repl.rs`
- `repl_start python -q` lolos allowlist (python ada). Setelah satu approval itu, setiap baris `input` dieksekusi interpreter: `import os; os.system('...')` di luar bahasa apa pun yang dipikirkan validator.
- Approval per-line tetap ada (needsApproval: true), jadi tidak diam-diam - tapi user melihat "satu baris ke REPL" bukan "kode arbitrary". Di mode `all`, approval hilang total.
- Rekomendasi: warning khusus di UI approval saat tool repl mengirim ke interpreter, dan/atau daftarkan pola `import os`, `require('child_process')`, `os.system`, `subprocess` sebagai risk-flag di `checkShellCommand` untuk input repl.

### SEC-4 (MEDIUM) Default approval mode = `all`
- File: `src/modules/ai/lib/approvalPolicy.ts:90` (`DEFAULT_APPROVAL_MODE: ApprovalMode = "all"`), dipakai `src/modules/settings/store.ts:532`.
- `isAutoApproved` dengan mode `all` return true untuk SEMUA tool kecuali `delete_file` dan command yang `deletesFiles`. Fresh install = agent otonom penuh, termasuk `bash_run` dan `repl_send`.
- Bukti pergeseran tak terdokumentasi: JSDoc di enum yang sama menulis `"ask" ... The default.` sementara konstantanya `"all"`. Salah satu pasti basi.
- Rekomendasi produk: default `edits`; `all` hanya lewat pilihan eksplisit + indikator visual permanen (badge merah di status bar).

### SEC-5 (MEDIUM) Env-prefix `PATH=... <allowlisted>` membajak resolusi program
- File: `src-tauri/src/modules/shell/mod.rs` (segitik POSIX env prefix di `validate_shell_command`, komentar "Skipping cannot launder a program").
- `PATH=<workspacedir> git status` lolos validasi (PATH adalah assignment, git allowlisted), tapi binari `git` yang ter eksekusi adalah lookup dari PATH yang dikontrol caller. `git` punya banyak vektor exec sendiri (`GIT_PAGER`, credential helper, `!` di pager).
- Catatan: vektor ini sebagian besar sudah tertutup oleh bypass path absolut SEC-1, tapi ini bypass yang BERBEDA dan lebih senyap.
- Rekomendasi: tolak assignment untuk variabel `PATH`, `LD_PRELOAD`, `LD_LIBRARY_PATH`, `PYTHONPATH`, `NODE_OPTIONS`, `RUBYOPT`, `PERL5OPT`, `GIT_*`, `BASH_ENV`, `ENV`, `PROMPT_COMMAND`.

### SEC-6 (MEDIUM) Write-guard melindungi `.git/` tapi tidak jalur eksekusi dari repo
- File: `src/modules/ai/lib/security.ts` (PROTECTED_DIRS), mirror `fs/security.rs`.
- Yang bisa ditulis agent dan dieksekusi otomatif oleh tooling: `.github/workflows/*.yml`, `.vscode/settings.json` (VSCode "trusted folders"), `.gitattributes`/`.gitmodules` (git clone+filter), `package.json` scripts + lifecycle hooks (`prepare` jalan saat `pnpm install`), `.mcp.json`, dan `hooks.json` (SEC-1).
- Ini kelas bug yang sama dengan SEC-1: file data yang diam-diam adalah code. Minimal beri risiko-flag saat approval dialog menampilkan write ke path-path ini ("file ini dieksekusi otomatis oleh ...").

### NIT-1 `isOwnerUser` fallback grup (low, unreachable via /pair)
- `src/modules/telegram/telegramCommands.ts:87`: `Number(msg.chat.id) < 0` => true untuk semua anggota. `/pair` selalu men-set `ownerUserId` (line ~634), jadi grup yang dipair lewat UI normal tidak kena. Tetap footgun kalau `chatId` pernah ternilai grup tanpa owner (state lama / restore). Saran: fallback hanya berlaku untuk chat positif; grup tanpa ownerUserId = tolak.

### NIT-2 sqlite/duckdb dot-commands bisa menulis file
- `src-tauri/src/modules/sql.rs`: koneksi lokal sudah lewat `validate_read` + `require_authorized`, tapi query ` .output C:/x`, `ATTACH`, `readfile()`/`export_db()` (duckdb) bisa menulis ke luar. Jalur user-driven (SQL Explorer, approval UI), jadi MEDIUM-LOW. Saran: jalankan sqlite3 dengan `-readonly`, dan filter dot-command yang menyentuh fs kecuali allowlist kecil (`.headers`, `.mode`, `.tables`).

### NIT-3 `termigo secret --key <value>`
- `cli/cmd/termigo/main.go`: flag `--key` menaruh API key di argv (process listing + shell history). Sudah ada jalur prompt non-echo; pertimbangkan deprecate `--key` atau minimal peringatan saat dipakai.

## C. UX AI Chat: perbandingan vs pola Opencode / Zcode

Konteks: `CRUSH-ANALYSIS.md` + `OPR-ANALYSIS.md` sudah menelaah arsitektur Opencode/Crush. Bagian ini fokus INTERAKSI chat-nya, bukan backend. (Mesin riset web offline saat audit; klaim tentang Opencode/Zcode berasal dari pengetahuan model + doc lokal, tandai "verifikasi sendiri" sebelum jadi keputusan.)

Gap nyata yang terkonfirmasi ada di kode Termigo (grep `editMessage|regenerate|fork|rewind` di `src/modules/ai` = nol hasil):

### Prioritas 1 - kontrol percakapan (ini yang bikin Opencode terasa "dipegang")
1. **Edit & resend user message** dengan truncate run dari titik itu. Sekarang user cuma bisa nambah pesan baru; salah instruksi = sampah permanen di context.
2. **Rewind/checkpoint per user turn**. `git_checkpoint` sudah ada per-run; angkat jadi per-turn + simpan daftar file yang disentuh tiap turn, lalu tombol "undo ke sini" (restore file + truncate pesan). Opencode populer justru karena checkpoint/undo.
3. **Fork session dari satu titik** (branch percakapan untuk alternatif pendekatan), dengan daftar sesi samping (Opencode: `tab sessions`, `goto`).

### Prioritas 2 - navigabilitas transcript
4. **Timeline navigator**: daftar user-turn (mini-map di tepi chat, klik = lompat). Transcript agent 200+ part tanpa anchor itu menyebalkan; Opencode memisahkan "user turns" vs "agent steps" secara visual tegas.
5. **Compact tool lines, expand inline**: baris tool non-read sudah satu baris; samakan read/grep/search jadi `3 files read (expand)` per langkah, dengan diff stat (`+12 -3`) di gutter sebelum di-expand.
6. **Jump-to-latest pill + auto-scroll pause saat user scroll ke atas** (cek implementasi `AiChat.tsx` kalau belum ada, ini keharusan).

### Prioritas 3 - composer & status
7. **Mode switcher in-composer** (plan/build/ask ala Opencode agents): `agentsStore` sudah ada, tapi ekspos sebagai chip cepat di composer, bukan dialog terpisah.
8. **Context + cost meter real per-turn**: `ContextMeter`/`CostPanel` sudah ada; tampilkan delta per step (tokens in/out, biaya turn) di footer run, bukan kumulatif saja.
9. **Approval affordance**: badge permanen mode `all` (lihat SEC-4), dan preview diff satu-lini di kartu approval (banyak approval di-approve buta karena kartu terlalu ringkas).

### Prioritas 4 - fitur khas yang layak dicuri
10. **Terminal-native chat**: output perintah yang dirender ANSI-aware langsung di transcript (atau "peek di terminal tab" dari kartu tool). Ini keunggulan Termigo atas Opencode/Zcode; belum dieksplor.
11. **Queue steering** sudah ada (`QueuedSteerRow`); tambah tombol "steer now" (interrupt + selipkan) yang jadi idiom Zcode/Opencode saat agent salah arah.
12. **Run diff summary akhir**: daftar file yang berubah + link buka diff per-file setelah run selesai (data sudah ada di checkpoint/confirmation store; tinggal render).

## E. Patch diterapkan (sesi yang sama, 2026-10)

Keputusan produk yang disepakati sebelum eksekusi: **`DEFAULT_APPROVAL_MODE` TETAP `"all"`** (user menolak gate tambahan; friksi approval harus tetap nol). Yang dikerjakan: SEC-1, SEC-2, SEC-5.

### SEC-2 - selesai
`src/modules/telegram/mermaidImage.ts`: opsi initialize diekstrak jadi `MERMAID_INIT` (exported) dengan `securityLevel: "strict"`, disamakan dengan renderer chat. Test pengunci di `mermaidImage.test.ts`.

### SEC-5 - selesai
`src-tauri/src/modules/shell/mod.rs`: `validate_shell_command` sekarang menolak assignment ke nama variabel yang menentukan **program mana yang jalan** atau **kode apa yang di-load**-nya (`is_hijack_env_var`), baik bentuk POSIX (`PATH=... git`) maupun PowerShell (`$env:PATH = ...`, `${env:NODE_OPTIONS}=...`).
- List dibuat bedah, bukan sapu bersih: `CI=true`, `FOO=bar`, `RUST_LOG=debug`, `GIT_TERMINAL_PROMPT=0`, dan `NODE_OPTIONS=--max-old-space-size` tetap lolos. `NODE_OPTIONS` dinilai dari nilainya (hanya `--require`/`--import`/`--experimental-loader`/`--inspect`/`-r` yang ditolak), bukan dari namanya.
- Ini MEMBALIK keputusan lama yang terkunci test (`PATH=/usr/bin git status` sebelumnya di-assert OK). Alasannya dicatat di kode: sandbox sudah mengizinkan path absolut, jadi penolakan ini tidak menutup semua jalan, tapi menghilangkan varian yang *senyap* (string perintah tetap terbaca innocuous).
- Test baru: `validate_shell_command_refuses_env_that_hijacks_the_program` (11 kasus tolak + 3 kasus tetap-boleh).

### SEC-1 - selesai untuk jalur file-tool, SISA untuk jalur shell
- `src/modules/ai/lib/security.ts`: `AGENT_IMMUTABLE_CONFIG` = `.termigo/hooks.json` + `.termigo/approvals.json` ditolak di `checkWritable` (baca tetap terbuka; `memory.md`, skills, payload hooks tetap bisa ditulis). Semua tool mutating (`write_file`, `edit`, `multi_edit`, `move_file`, `copy_file`, `replace_in_files`, `create_directory`) sudah lewat fungsi ini, satu titik tutup semua.
- `src-tauri/src/modules/fs/security.rs`: mirror untuk `hooks.json` SAJA. `approvals.json` sengaja tidak dideny di layer Rust karena tombol "allow for this project" di dialog approval menulis file itu lewat `fs_write_file` yang sama, dan layer ini tidak bisa membedakan klik user dari panggilan agent. Alasannya ditulis di kode.
- Test: `hooks_config_cannot_be_written_but_stays_readable` (Rust) + describe `agent-immutable config under .termigo` (TS).
- **Sisa yang belum tertutup (jujur):** deny-list ini hanya mengikat jalur fs. Shell sandbox tidak mengonsultasikan deny-list fs, jadi `cp evil.json .termigo/hooks.json` (keduanya argumen program yang di-allowlist) tetap tidak tersentuh. Selain itu `hooks.json` bawaan repo yang di-clone tetap fire tanpa prompt - itu model trust yang sudah ada. Perbaikan yang benar-benar menutup adalah **trust-gate hooks** (hash config, minta konfirmasi saat berubah), yang butuh UI.
