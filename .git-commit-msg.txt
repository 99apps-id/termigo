fix(approval): reconcile expiry timers on every transcript change, not just assistant turns

A timer armed for an approval awaiting an answer was only reconciled inside the
effect branch that runs when the last message is an assistant turn. That branch
returns early on exactly the shape produced by answering an approval in the app,
resolving it through /approve, or resuming past it: the last message becomes the
user's. The timer therefore stayed armed and fired minutes later against an id
the run had already left behind, responding to a question nobody had asked.

The deadlines now live in their own effect, keyed on the transcript, so an
approval that is no longer pending always clears its timer. `pendingApprovalIds`
and `reconcileApprovalTimers` are composed rather than reimplemented, and the
test asserts the pair on the move-on shape.

Found while reviewing a concurrent commit that clears `pendingApprovals` on
`resumeRun` - the same desync from the other direction.

Gates: pnpm check-types, pnpm test.
